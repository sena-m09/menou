# ベースラインの記録と、`menou run` が使うベースライン

- 日付：2026-11-06
- 状態：採用

## 背景

ベースラインはセッションごとに記録しますが、次の 2 点が決まっていませんでした。

1 つ目は、`menou run` がどのセッションのベースラインを使うかです。`menou run` はチェックに `MENOU_BASELINE` を渡しますが、エージェントが Bash から呼ぶときは、フックと違って入力の JSON でセッション ID を受け取れません。

2 つ目は、ベースラインを上書きする条件です。[03-architecture.md](../03-architecture.md) には「再開やコンパクションでは上書きしない」とだけあり、Claude Code の clear や fork をどう扱うかが書かれていませんでした。

[05-agents.md](../05-agents.md) で確かめた Claude Code の仕様は次のとおりです。

- Bash ツールで実行したコマンドにも `CLAUDE_CODE_SESSION_ID` が渡り、値はフックの入力の `session_id` と同じ
- SessionStart の `source` が `resume` と `compact` のときは `session_id` が前と同じで、`clear` と `fork` のときは新しくなる

`menou run` が使うベースラインについて、次の 2 つを比べました。

| | リポジトリで最後に記録されたものを使う | セッション ID で選ぶ |
| --- | --- | --- |
| 1 つの worktree で 1 つのセッションを動かすとき | 同じ結果になる | 同じ結果になる |
| 1 つの worktree で 2 つのセッションを同時に動かすとき | 後から始めたセッションのベースラインが、もう一方でも使われる | それぞれのセッションのベースラインを使う |
| セッション ID を受け取れないとき | 使える | 別の決め方が要る |

上書きの条件は、SessionStart の `source` ごとに扱いを決める方法と、`source` を見ずにセッション ID だけで決める方法を比べました。

## 決定

- ベースラインは、セッション ID ごとに 1 回だけ記録する。SessionStart で、そのセッション ID のベースラインがまだなければ記録し、あれば何もしない。`source` は見ない
- `menou run` は、環境変数 `CLAUDE_CODE_SESSION_ID` が渡っていれば、そのセッションのベースラインを `MENOU_BASELINE` に入れる
- セッション ID が渡っていないとき、またはそのセッションのベースラインがないときは、その worktree で最後に記録されたベースラインを使う
- その worktree にベースラインが 1 つもなければ、`MENOU_BASELINE` を渡さない
- ベースラインは、worktree ごとの git ディレクトリの `menou/sessions/<セッション ID>/` に置く

`resume` と `compact` ではセッション ID が変わらないので、ID だけで決めても「再開やコンパクションでは上書きしない」が満たされます。`clear` と `fork` では ID が新しくなるので、新しいセッションとしてその時点の作業ツリーを記録します。`source` を見ないので、menou を入れる前に始めたセッションを再開したときも、その時点で記録されます。

セッション ID が渡っていないのは、人が端末から `menou run` を実行したときや、Codex から実行したときです。このときも、最後に記録されたベースラインを使えば、レビューの差分を作れます。`MENOU_BASELINE` はレビューで差分を作るためだけに使い、チェックの記録はベースラインに関係なくフィンガープリントで決まります。そのため、別のセッションのベースラインを使っても、困るのはレビューに渡す差分の範囲がずれることだけです。

## 影響

1 つの worktree で 2 つの Claude Code のセッションを同時に動かしても、それぞれのベースラインが混ざりません。

`clear` や `fork` のあとは、その時点の作業ツリーがベースラインになります。clear の前にコミットしていない変更は、新しいセッションの Stop では判定されません。clear の前の変更は、前のセッションの Stop で判定されています。判定されずに残るのは、人が中断したときと、`maxBlocks` に達して完了させたときの変更です。

Codex がシェルのコマンドにセッション ID を渡すかと、Codex の SessionStart の種類は、まだ確かめていません。M3 で確かめ、渡っていればその環境変数も `menou run` で読みます。それまで Codex から実行した `menou run` は、最後に記録されたベースラインを使います。

セッションごとのディレクトリは、セッションが終わっても残ります。消し方は、たまって困るようになったら決めます。
