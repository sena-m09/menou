# フィンガープリントの計算方法と paths の解釈

- 日付：2026-11-06
- 状態：採用

## 背景

フィンガープリントは、チェックの `paths` に入るファイルの一覧と、それぞれの中身から計算します。コミットしていない変更とまだ追跡していないファイルは含め、`.gitignore` の対象は除きます。利用者が `git add` した状態は変えません。

[03-architecture.md](../03-architecture.md) では、一時インデックスに `git add -A` して `git write-tree` で tree を作り、`git ls-tree -r <tree> -- <paths>` の出力をハッシュするとしていました。ところが、この方法では [04-config.md](../04-config.md) の例にある `src/**` や `eslint.config.*` が、1 つのファイルにも一致しません（git 2.39 で確認）。`git ls-tree` が glob を解釈しないためです。同じ一時インデックスに `git ls-files -s -- <paths>` を使えば、glob が効きます。

ファイルの選び方として、次の 2 つを比べました。

| | チェックごとに `git ls-files -s` を実行する | `git ls-files -s` を 1 回だけ実行し、JS の glob ライブラリで振り分ける |
| --- | --- | --- |
| paths の意味 | git の pathspec のまま。`:(exclude)` も使える | ライブラリの解釈になり、git とずれる。`:(exclude)` は使えない |
| 速さ | チェックの数だけ git を起動する。menou のリポジトリ（34 ファイル）では 1 回あたり約 11 ms | git の起動は 1 回で済む |

作業ツリーの状態の取り方としては、Node でファイルをたどってハッシュする方法と、`git stash create` も考えました。前者は `.gitignore` の解釈を自分で作り直すことになります。後者は、まだ追跡していないファイルを含められません。

paths の `*` の解釈も決める必要がありました。git の既定では `*` が `/` をまたぐので、`*.md` が `docs/x.md` にも一致します。環境変数 `GIT_GLOB_PATHSPECS=1` を付けると、`*` はディレクトリをまたがなくなり、`**` だけがまたぎます。

## 決定

- 一時インデックスに `git add -A` し、チェックごとに `git ls-files -s -- <paths>` の出力をハッシュする
- 一時インデックスは、作業ツリーの外（`git rev-parse --git-dir` が返すディレクトリの中）に置く
- 作業ツリー全体の状態は、同じ一時インデックスから `git write-tree` で取る。ベースラインと比べるときに使う
- `paths` は `GIT_GLOB_PATHSPECS=1` を付けて、glob として解釈する。`:(exclude)` のような pathspec の magic は、そのまま使える

paths の意味を git に任せておけば、menou の側で書き方の仕様を作って保たずに済みます。git の起動が増える分は、1 チェックあたり 10 ms ほどです。一時インデックスを作業ツリーの中に置くと、`git add -A` が一時インデックスのファイル自体を拾ったので、外に置きます。

## 影響

paths の書き方が `.gitignore` に近くなり、`*.md` はリポジトリの直下の Markdown だけに一致します。サブディレクトリまで含めたいときは `**/*.md` と書きます。git の既定とは違うので、[04-config.md](../04-config.md) に書き方を載せます。

チェックの数だけ git を起動するので、チェックが多いほど Stop のたびの待ち時間が延びます。チェックが 3 つなら約 35 ms です。遅さが問題になったら、git の起動を 1 回にまとめる方法に切り替えられます。その場合は paths の意味が変わるので、新しい ADR を書きます。

実際のインデックスを写してから一時インデックスとして使えば、ファイルの stat の情報を使い回せるので、`git add -A` が速くなる見込みです。実装するときに測ります。

どのファイルにも一致しない paths をエラーにするかは、設定の読み込みを作るときに決めます。
