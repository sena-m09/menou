# 設定ファイルが不正なときの挙動

- 日付：2026-11-06
- 状態：採用

## 背景

`.menou.json` が不正なときに、完了をブロックするか、警告して通すかが決まっていませんでした。不正には、JSON として読めない、スキーマに合わない、[04-config.md](../04-config.md) のバリデーションのルール（`id` の重複、存在しない `id` を指す `needs`、`needs` の循環）に反する、の 3 つがあります。

次の 3 つを比べました。

| | ブロックする | 警告して通す | ブロックし、`maxBlocks` に達したら通す |
| --- | --- | --- | --- |
| 設定を壊したとき | ゲートは外れない | ゲートが外れる | `maxBlocks` に達するまでは外れない |
| エージェントが止まり続けるか | 止まり続ける | 止まらない | `maxBlocks` で止まらなくなる |

エージェントは設定を直せません。M4 で、エージェントによる `.menou.json` の編集を拒否する予定だからです。

## 決定

- 設定ファイルが不正なときは完了をブロックし、ブロックが `maxBlocks` に達したら完了を許可する
- このときの `maxBlocks` は、設定に書かれた値ではなく既定の 3 を使う
- 理由文では、どこが不正かを示し、人に直してもらうよう伝える
- `menou run` と `menou status` は、どこが不正かを出力し、エラーの終了コードで終わる

ブロックし続けると、直せないエージェントが止まり続けます。警告して通すと、設定を壊しただけでゲートが外れます。[02-concept.md](../02-concept.md) の「詰まったら人に渡す」に合わせ、決まった回数だけブロックしてから人に渡します。

不正な設定に書かれた値は信用できないので、`maxBlocks` も既定の値を使います。

`.menou.json` がないリポジトリでは、これまでどおり何もしません。

## 影響

設定を壊しても、ゲートが黙って外れることはありません。ただし、`maxBlocks` に達するまでの間、エージェントは同じ理由でブロックされ続けます。

`maxBlocks` を大きくしているプロジェクトでも、設定が不正な間は 3 回で通ります。
