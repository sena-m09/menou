# 不合格のときに、チェックの出力や詳細をエージェントに渡す方法

- 日付：2026-11-09
- 状態：採用

## 背景

Stop で不合格やエラーになったチェックについて、エージェントが直すための手がかりをどう渡すかが決まっていませんでした。

1 つ目は、Stop のフックの中で実行した inline 方式のチェックの出力です。[03-architecture.md](../03-architecture.md) は、チェックの出力を「そのまま端末に流す」としていました。これは `menou run` から実行したときの話です。Stop のフックでは、menou の標準出力をエージェントが判定の JSON として読むので、チェックの出力をそこに流せません。次の 3 つを比べました。

| | 出力を捨て、`menou run <id>` を実行するよう伝える | 出力をファイルに書き、その場所を伝える | 出力の末尾を理由文に入れる |
| --- | --- | --- | --- |
| エージェントが出力を見る方法 | `menou run` の結果としてそのまま見える | ファイルを読む | 理由文の中で見える |
| チェックの実行 | 不合格のたびに、もう 1 回実行する | 1 回で済む | 1 回で済む |
| 新しく作るもの | ない | ファイルへの書き出しと、古いファイルの扱い | 末尾の切り出し方 |

2 つ目は、別の worktree で取った不合格の記録を使ったときの案内です。記録は worktree をまたいで共有しますが、`MENOU_OUT` のディレクトリは worktree ごとにあります（[20261106-record-location.md](20261106-record-location.md)）。そのため、この worktree の `menou/out/<id>/` には、詳細がないか、前に別の状態で取った古い詳細が残っています。次の 2 つを比べました。

- 記録に、それを取った worktree を残し、同じ worktree で取った記録のときだけ詳細の場所を伝える
- どこで取った記録でも、`menou run <id>` で取り直すよう伝える

## 決定

- Stop のフックの中で実行した inline 方式のチェックの出力は捨てる。不合格やエラーのときは、理由文で `menou run <id>` を実行して出力を確かめるよう伝える
- チェックの記録に、それを取った worktree の git ディレクトリを残す
- 不合格の記録を見つけたとき、この worktree で取った記録なら `MENOU_OUT` の詳細の場所を伝える。別の worktree で取った記録なら、`menou run <id>` で取り直すよう伝える

inline 方式は速いチェックに向けた方式なので、もう 1 回実行しても負担は小さく済みます。`menou run` の出力はエージェントの Bash の結果にそのまま出るので、ファイルを探して読む手間もありません。

## 影響

Stop の中でチェックの出力を扱う仕組みを新しく作らずに済みます。ログのファイルが古いまま残ることもありません。

inline 方式のチェックが不合格になると、Stop と `menou run` で 2 回実行されます。重いチェックを inline 方式にすると、この分だけ待ち時間が延びます。

レビューのような重い evidence 方式のチェックは、同じ worktree で取った記録なら、取り直さずに詳細を読めます。ただ、記録はチェックの `id` とフィンガープリントの組ごとに 1 つなので、別の worktree が同じ状態で取り直すと上書きされます。そのときは、この worktree に詳細が残っていても、取り直すよう伝えることになります。

[20261106-block-count-and-errors.md](20261106-block-count-and-errors.md) では、チェックがエラーになったときの理由文で「出力の場所」を伝えるとしていました。inline 方式のチェックでは、`menou run <id>` を実行するよう伝えることがこれにあたります。

worktree を残していない記録は、別の worktree で取った記録として扱います。
