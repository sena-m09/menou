# inline 方式のタイムアウトの既定値

- 日付：2026-11-06
- 状態：採用

## 背景

[04-config.md](../04-config.md) では、チェック定義の `timeout` を省いたときの既定値が「未定」になっていました。inline 方式のチェックは Stop のフックの中で実行するので、エージェント側のフックがタイムアウトする前に終わらせる必要があります。ところが、フックのタイムアウトの既定値は、M2 で Claude Code の仕様を確かめるまで分かりません。

一方、[20261106-fingerprint-scope.md](./20261106-fingerprint-scope.md) では、既定値を補った `timeout` をフィンガープリントに含めると決めました。そのため、M1 で設定の読み込みを作る時点で、何かしらの既定値が要ります。

次の 2 つを比べました。

| | 仮の値を決めて、M2 で見直す | M1 ではタイムアウトなしにし、M2 で決める |
| --- | --- | --- |
| M1 の実装 | 既定値を補う処理を最初から作れる | 「タイムアウトなし」という特別な扱いが要る |
| M2 で値を変えたとき | `timeout` を省いたチェックの記録が一度だけ無効になる | 同じ |

## 決定

- `timeout` の既定値を、仮に 120 秒にする
- チェックごとの `timeout` には、120 秒より長い値も短い値も書ける
- トップレベルに、全チェックの既定値を変える `timeout` は置かない
- 時間切れになったチェックは、チェック自体のエラーとして扱う
- M2 でフックのタイムアウトの既定値を確かめたら、120 秒を見直す。値を変えるときは、この ADR を新しい ADR で置き換える

inline 方式は Lint や型チェックのような速いもの向けなので、大きめのリポジトリの Lint でも収まる長さにしました。トップレベルの `timeout` は、設定の項目を増やさないため、必要になるまで置きません。

## 影響

M2 で既定値を変えると、`timeout` を省いていたチェックの記録が一度だけ無効になります。取り直せば済みます。

全チェックの既定値をまとめて変えたいプロジェクトは、チェックごとに `timeout` を書く必要があります。困る場面が出てきたら、トップレベルの `timeout` を足します。
