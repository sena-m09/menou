# Node.js の下限を 22 に上げる

- 日付：2026-11-06
- 状態：採用

## 背景

[20261102-implementation-language.md](./20261102-implementation-language.md) では、menou を動かすのに必要な Node.js の下限を 16.0.0 にしました。[20261104-lint-and-formatter.md](./20261104-lint-and-formatter.md) では、この下限に合わせて `@types/node` を 16 系に固定し、Node.js 16 にない API を型エラーにしています。

ところが、Node.js 16・18・20 はどれもサポートが終わっています。今サポートされている中でいちばん古いのは 22 で、サポートは 2027-04 まで続きます。

また、`@types/node` を 16 系に固定しているので、install のたびに警告が出ていました。Vitest が `@types/node` 22 以上を、Vite が 20.19 以上を求めているためです。

下限を 20 にする案も比べました。20 では、`@types/node` を 20 系に固定するので、Vitest の警告が残ります。

## 決定

- Node.js の下限を 22.0.0 にする
- `@types/node` を 22 系に上げる
- `tsconfig.json` の `target` と `lib` を ES2024 にする。Node.js 22.0.0 で ES2024 の機能がすべて動くことを確かめた
- `pnpm test:floor` では、Node.js 22.0.0 で起動できることを確かめる

この決定で、[20261102-implementation-language.md](./20261102-implementation-language.md) の「決定」にある下限の Node.js 16.0.0 は、22.0.0 に代わります。[20261104-lint-and-formatter.md](./20261104-lint-and-formatter.md) の「決定」にある `@types/node` の 16 系への固定も、22 系に代わります。Node.js にない API を `@types/node` のメジャー version で止める方法は変わりません。

M1 の実装に入る前に上げておけば、あとで書き直す量が少なくて済みます。

## 影響

`structuredClone` や `import.meta.dirname` のように、Node.js 17〜22 で増えた API が使えるようになります。install の警告もなくなります。

PATH にある `node` が 22 より古い人は、menou を起動できなくなります。`bin/menou` は `node` があるかしか見ないので、古い `node` では分かりにくいエラーで落ちます。version を見て案内を出すかは、別に決めます。

22.x の途中で増えた API は止められません。`@types/node` 22 系の型は 22 系の最新に合わせてあるためです。16 系のときと同じく、`pnpm test:floor` で見つけられるのは、`--version` で起動したときに通る範囲だけです。
