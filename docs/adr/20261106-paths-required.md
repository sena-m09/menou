# paths を必須にする

- 日付：2026-11-06
- 状態：採用

## 背景

[04-config.md](../04-config.md) では、チェック定義で `paths` を省くと全ファイルが対象になるとしていました。一方、[01-overview.md](../01-overview.md) の成功の判断基準には「関係ない作業（ドキュメントだけの修正など）では邪魔をしない」とあります。`paths` を書かないチェックは、ドキュメントだけを直したときにも要求されるので、この基準と合いません。

次の 3 つを比べました。

| | 全ファイルのまま | 既定で除外するパターン（`*.md` など）を持つ | 必須にする |
| --- | --- | --- | --- |
| 書き忘れたとき | 関係ない作業でも要求される | 書いていない除外が効く | エディタとバリデーションで指摘される |
| 設定を読んで範囲が分かるか | 分かる | 除外が書かれていないので分からない | 分かる |
| 困るプロジェクト | ないが、書き忘れに気づきにくい | ドキュメントのサイトを作るプロジェクトでは、Markdown を直しても検証されない | ない |

## 決定

- チェック定義の `paths` を必須にし、1 件以上書くことにする
- 全ファイルを対象にしたいときは `["**"]` と書く

## 影響

チェックごとに 1 行増えますが、どのファイルを変えたときに要求されるかが設定から読み取れます。

`paths` を省いた設定や空の配列は、不正な設定として扱われます。
