# チェックの範囲がベースラインから変わったかの比べ方

- 日付：2026-11-09
- 状態：採用

## 背景

Stop の判定フローでは、チェックの `paths` の範囲がベースラインから変わっていなければ、そのチェックを対象外にします。ベースラインとして記録するのは、作業ツリー全体の tree のハッシュ 1 つだけです（[20261106-baseline-per-session.md](20261106-baseline-per-session.md)）。チェックごとに範囲が変わったかをどう比べるかは、決まっていませんでした。

比べ方は、次の 2 つを比べました。

| | ベースラインの tree と今の tree を、今の `paths` で比べる | SessionStart でチェックごとのフィンガープリントも記録し、今のものと比べる |
| --- | --- | --- |
| 新しく記録するもの | ない。どちらの tree も今の実装で作っている | チェックごとのフィンガープリント |
| セッションの途中で足したチェック | 比べられる | ベースラインがないので比べられない |
| チェック定義を変えたとき | ファイルが変わっていなければ対象外のまま | 変わったことになる |

`git diff-tree` は、git 2.39.5 の一時リポジトリで確かめました。`-r` を付けると、`src/*`・`src/**`・`**/*.md`・`*.md`・`:(exclude)docs/**` のどれも、[04-config.md](../04-config.md) の「paths の書き方」の表どおりに一致しました。`-r` を付けないと、`src/*` が `src/a/x.ts` の変更に反応し、`**/*.md` が `docs/d.md` の変更に反応しませんでした。

セッションの途中で `.menou.json` が変わったときの扱いも決まっていませんでした。たとえば `paths` を狭めて、編集したファイルを範囲から外すと、そのチェックは対象外になって完了できてしまいます。M4 で `.menou.json` の編集を `PreToolUse` で拒否しますが、Bash からの書き込みは防げません。

ベースラインの tree は、どの ref からも参照されないので、`git gc` で消されることがあります。既定では、作ってから 2 週間を過ぎると消されます。

## 決定

- チェックの範囲が変わったかは、ベースラインの tree と今の tree を、今の `paths` で比べて決める。`GIT_GLOB_PATHSPECS=1` を付けて `git diff-tree -r --quiet <ベースライン> <今の tree> -- <paths>` を実行する
- `.menou.json` がベースラインから変わっていたら、すべてのチェックを範囲内として扱う
- ベースラインがないとき、またはベースラインの tree が消えていて比べられないときも、すべてのチェックを範囲内として扱う。このときは、「作業ツリーがベースラインから変わっていなければ通す」の判定もしない
- ベースラインの tree を消されないようにする ref（`refs/menou/…` など）は作らない

## 影響

ベースラインのほかに新しく記録するものはありません。セッションの途中で足したチェックや、`paths` を広げたチェックも、今の `paths` で比べられます。

`.menou.json` を書き換えると、そのセッションでは、すべてのチェックを満たすまで完了できなくなります。`hint` のように合否に関係しない項目を直しただけでも同じです。ただ、合格した記録はフィンガープリントで使い回すので、変更のないチェックを取り直すことはありません。

ベースラインがない、または消えていたときは、安全な側に倒してすべてのチェックを求めます。2 週間を超えて再開したセッションや、menou を入れる前に始めたセッションで起こります。

ref を作れば `git gc` で消されなくなりますが、`git log --all` などに menou の tree が出てくるので採りません。
