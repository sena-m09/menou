# 記録の置き場所と、ブランチや worktree をまたいだ再利用

- 日付：2026-11-06
- 状態：採用

## 背景

[03-architecture.md](../03-architecture.md) では、記録を `.git/menou/` に置くとしていました。ところが git worktree では、git ディレクトリが 2 つに分かれます。worktree ごとの git ディレクトリ（`git rev-parse --git-dir`）と、すべての worktree で共有する git ディレクトリ（`git rev-parse --git-common-dir`）です。どちらに置くかで、ある worktree で取った記録を別の worktree で使えるかが変わります。

ブランチを切り替えたあとにフィンガープリントが一致した場合に、前の記録を使ってよいかも決まっていませんでした。

menou が置くデータには、性質の違う 3 種類があります。

| データ | 中身 | 決まるもの |
| --- | --- | --- |
| チェックの結果 | フィンガープリントと合否 | チェック定義とファイルの内容だけ |
| セッションごとのデータ | ベースライン、ブロック回数 | その worktree で動いているセッション |
| `MENOU_OUT` で渡すディレクトリ | チェックが書き出した詳細（レビューの指摘など） | その worktree での実行 |

## 決定

- チェックの結果は、共有する git ディレクトリの `menou/` に置く
- フィンガープリントが一致する記録は、ブランチや worktree が違っても使い回す
- セッションごとのデータと `MENOU_OUT` のディレクトリは、worktree ごとの git ディレクトリの `menou/` に置く
- チェックの結果はフィンガープリントごとに別のファイルにし、一時ファイルに書いてから rename で置く

フィンガープリントはチェック定義とファイルの内容だけから決まるので、一致すれば同じ入力を検証したことになります。そのため、ブランチを戻したときや別の worktree でも、取り直さずに済むようにします。

セッションごとのデータは、worktree ごとに別のセッションが動くので、混ざらないように分けます。`MENOU_OUT` のディレクトリも分けるのは、2 つの worktree で同じチェックを同時に動かしたときに、書き出したファイルが混ざらないようにするためです。

結果のファイルを rename で置くのは、複数の worktree から同時に書いても、読む側が書きかけのファイルを見ないようにするためです。

git worktree を使っていないリポジトリでは、2 つのディレクトリはどちらも `.git` なので、置き場所は `.git/menou/` のままです。

## 影響

ブランチを切り替えたり、worktree を分けて並行で作業したりしても、同じコードに対する E2E やレビューを取り直さずに済みます。

フィンガープリントに入らないものの違いは見分けません。たとえば `node_modules` の中身や環境変数が worktree ごとに違っても、ファイルの内容が同じなら同じ記録を使います。

ほかの worktree で取った記録を使ったときは、`MENOU_OUT` に書き出された詳細がこの worktree からは見えません。不合格の記録を使い回したときの理由文の案内は、判定フローを作るときに決めます。

2 つのディレクトリは `git rev-parse --path-format=absolute --git-dir --git-common-dir` で取ります。worktree では、`--path-format=absolute` を付けないと相対パスが返ることがあります。

Claude Code の sandbox の中から `menou run` を実行したときに、共有する git ディレクトリへ書けるかは、M2 でサンプルリポジトリを使って確かめます。
