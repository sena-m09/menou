# プロジェクト概要

menou は、AI コーディングエージェントが「決められた検証を、今のコードに対して通した」状態でなければ作業を完了できないようにする仕組みです。Claude Code と Codex の両方で同じように動き、何を検証するかはプロジェクトごとに自由に差し替えられます。

## 背景

AI エージェントに実装を任せると、テストを実行していないのに「テストは通りました」と報告したり、テストが通ったあとにさらにコードを修正して完了したりすることがあります。指示ファイル（`CLAUDE.md` や `AGENTS.md`）に「テストを通してから完了すること」と書いても、それはお願いにすぎず、守られる保証はありません。

また、E2E テストのような重い検証は CI に載せにくく、ローカルで回すことになりがちです。ローカル実行は「回すかどうかが人の規律に依存する」という弱点を抱えます。

## 解決したい課題

- エージェントが検証を飛ばしても完了できてしまう
- 検証後にコードが変わっても、古い結果のまま完了できてしまう
- 何を検証すべきかはプロジェクトによって違う（Lint、E2E、別エージェントによるレビューなど）のに、毎回仕組みから作り直している
- Claude Code と Codex でフックの仕様が微妙に違い、両方に対応させる手間がかかる

## 達成したいこと

- 完了条件をプロジェクトごとの設定ファイルで宣言でき、エージェントはそれを満たすまで完了できない
- 判定はモデルの自己申告ではなく、ツールが生成した記録とコードの状態のハッシュで行う
- 検証の中身（何をゲートするか）と、それを強制する基盤を分離し、チェックを自由に追加・差し替えできる
- Claude Code と Codex のどちらからでも、同じ設定・同じ判定で動く

## ゴールと非ゴール

| | 内容 |
| --- | --- |
| ゴール | ローカルの AI 実装ワークフローに、宣言的な完了条件と鮮度チェックを導入する |
| ゴール | Lint・E2E・エージェントレビューなどを、同じ仕組みのチェックとして扱えるようにする |
| ゴール | Claude Code と Codex の両方に対応する |
| 非ゴール | CI の代替になること。マージ時の最終的な関門は CI など別の層が担う |
| 非ゴール | エージェントのあらゆる抜け道を完全に塞ぐこと。Bash 経由の書き込みなどは「うっかり」を防ぐ層にとどめる |
| 非ゴール | 途中の作業手順を厳密に縛ること（オートマトン的な経路制御）。必要になってから検討する |

## 成功の判断基準

- エージェントが検証を実行せずに完了しようとすると、確実にブロックされる
- 検証後にコードを変更すると、再検証するまで完了できない
- チェックの追加が、基盤のコードを変えずに設定ファイルの編集だけで済む
- 同じリポジトリで Claude Code と Codex を切り替えても、同じ判定結果になる
- 関係ない作業（質問に答えただけ、ドキュメントだけの修正など）では邪魔をしない
