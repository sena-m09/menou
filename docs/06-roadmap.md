# ロードマップと未決事項

まず Claude Code だけで「inline の Lint が完了をブロックできる」状態を最短で作り、そこから evidence 方式、Codex 対応、プリセットの順に広げます。各マイルストーンは、完了条件を満たしてから次に進みます。

## マイルストーン

1. **M0 リポジトリの準備**
   `docs/` を配置し、プロジェクトの雛形、テスト基盤、Lint を整える。完了条件：空のテストが CI なしでローカルで通る。
2. **M1 コアの最小実装**
   設定の読み込みとバリデーション、作業ツリーのハッシュとチェックごとのフィンガープリント、結果の保存、`menou run <id>` と `menou status`。完了条件：フィンガープリントがファイル変更・範囲外の変更・設定変更に正しく反応することを単体テストで確認できる。
3. **M2 Claude Code での Stop ゲート**
   `menou hook session-start` と `menou hook stop`、inline と evidence の判定、`needs`、`maxBlocks`。完了条件：サンプルリポジトリで、Lint エラーを残したまま Claude Code が完了しようとするとブロックされる。
4. **M3 Codex 対応**
   アダプタ層を分離し、Codex の出力形式に対応する。`menou doctor` でフックの登録と信頼状態を確認する。完了条件：同じサンプルリポジトリで、Codex でも同じ判定になる。
5. **M4 自己防衛と案内**
   `PreToolUse` による設定と記録の保護、SessionStart でのチェック一覧の案内。完了条件：エージェントが `.menou.json` を編集しようとすると拒否される。
6. **M5 プリセット**
   `agent-review`（再帰防止、読み取り専用、構造化された判定）と E2E の設定例。完了条件：Claude Code の実装を Codex がレビューし、指摘があればブロックされる。
7. **M6 配布**
   両エージェント向けのプラグインマニフェスト、導入手順。完了条件：別のマシンで導入手順どおりに入れて動く。

## 未決事項

- [ ] リポジトリの置き場所。独立したリポジトリにするか、両対応プラグインをまとめるリポジトリに収録するか
- [ ] 設定ファイルが不正なときの挙動。ブロックする（安全側）か、警告して通す（邪魔をしない側）か
- [ ] inline 方式のタイムアウトの既定値
- [ ] ブランチを切り替えたときの記録の扱い。フィンガープリントが一致すれば再利用してよいか
- [ ] フィンガープリントに含める範囲。`.gitignore` 対象のファイルや、E2E の記録データの扱い
- [ ] CI 側で実行記録を確認する仕組みをスコープに含めるか
- [ ] 最初に試す実プロジェクト
- [ ] Windows への対応

## リスク

| リスク | 影響 | 対策 |
| --- | --- | --- |
| エージェントのフック仕様が変わる | 判定が動かなくなる | アダプタ層に閉じ込め、`doctor` と統合テストで早く気づく |
| Codex でフックが未信頼のまま | ゲートが黙って動かない | `doctor` で検知し、SessionStart で警告する |
| エージェントがテストを書き換えて通す | 検証が形骸化する | テストファイルの変更を人の確認対象にするチェックを用意する |
| ゲートがうるさすぎる | 使われなくなる | `paths` と `severity: warn` で段階的に導入する |
| Bash 経由で記録や設定が改ざんされる | ゲートが無効化される | 完全な防御は狙わず、CI など別の層で補う |
