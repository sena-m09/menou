# menou ドキュメント

menou は、AI コーディングエージェントが「決められた検証を、今のコードに対して通した」状態でなければ作業を完了できないようにする仕組みです。Claude Code と Codex の両方で動き、何を検証するかはプロジェクトごとに差し替えられます。

## 名前について

Agent gate → Agate → 瑪瑙 → menou

AI エージェントが完了する前に通る関門（Agent gate）を縮めると、宝石の瑪瑙を表す英単語 agate になります。その和名「めのう」をローマ字にしたものが menou です。

名前は次のように統一します。

| 対象 | 名前 |
| --- | --- |
| CLI | `menou` |
| npm パッケージ | `@sena-m09/menou` |
| 設定ファイル | `.menou.json` |
| 記録の保存場所 | `.git/menou/`（git worktree では、セッションごとのデータと `MENOU_OUT` のディレクトリを `.git/worktrees/<名前>/menou/` に置く） |
| 環境変数の接頭辞 | `MENOU_` |

## ドキュメントの扱い

このディレクトリの内容を設計の正とします。ファイルによって寿命が違うので、次の表に従って扱ってください。

| ファイル | 種類 | 扱い |
| --- | --- | --- |
| 02-concept.md | 育てていく | 設計原則を変えるときだけ更新する |
| 03-architecture.md | 育てていく | 実装と常に一致させる |
| 05-agents.md | 育てていく | 両エージェントの仕様変更に合わせて更新する |
| 04-config.md | 形を変えて残す | 実装後は利用者向けのリファレンスにする。`src/config-schema.ts` のスキーマを正とし、ドキュメントは `schema.json` と同じくそこから生成する形に寄せる |
| 01-overview.md | 形を変えて残す | 背景と目的はリポジトリのトップの README に移す。成功の判断基準は達成したら削除する |
| 06-roadmap.md | 役割を終えたら消す | 完了した項目、決まった項目から消していく |

### 更新のルール

1. マイルストーンが完了したら、06 から該当項目を消す
2. 未決事項が決まったら ADR を書き、06 から消す
3. 実装と 03〜05 がずれる変更をしたら、同じコミットでドキュメントも直す

### ADR（決定の記録）

決まったことは `docs/adr/` に、書いた日付（yyyymmdd）と短い英語の名前をつないだファイル名で残します（例：`20261102-invalid-config-behavior.md`）。ADR は書いたら書き換えません。決定を覆すときは新しい ADR を書き、古い ADR の状態欄に「20261120-xxx.md により置き換え」のように置き換え先のファイル名を記します。

書くときは [`adr/template.md`](./adr/template.md) を写して使ってください。
