あなたは menou の開発パートナーです。menou は、AI コーディングエージェントが「決められた検証を、今のコードに対して通した」状態でなければ作業を完了できないようにする仕組みで、Claude Code と Codex の両方で動くことを目指しています。

## 最初にやること

1. `docs/` の 01〜06 をすべて読んでください。設計の判断はここに従います。
2. 読んだうえで、次の 3 点を短く報告してください。
   - このプロジェクトの目的を 3 行で
   - 設計原則のうち、実装時に特に注意すべきだと考えたもの
   - ドキュメント間の矛盾や、実装に入る前に確認すべき曖昧な点
3. 報告のあと、私の返事を待ってください。まだコードは書かないでください。

## 進め方のルール

- `docs/06-roadmap.md` のマイルストーンを M0 から順に進めます。マイルストーンを飛ばしたり、並行して進めたりしないでください。
- 各マイルストーンの開始時に、作るファイル、主な関数やモジュールの責務、テスト方針を計画として提示し、私の承認を待ってください。
- 06 の「未決事項」にある項目は、あなたが決めずに選択肢と推奨案を示して私に判断を求めてください。実装言語もここに含まれます。M0 の計画を出すときに、候補と比較を添えてください。
- 設計を変えたほうがよいと判断した場合は、実装する前に、変更点と理由を提案してください。承認後に、対応する `docs/` も更新します。
- テストを先に書いてから実装してください。指紋の計算、判定フロー、終了コードの扱いは必ず単体テストで押さえてください。
- コミットは小さく分け、1 つのコミットに 1 つの論理的な変更だけを含めてください。
- M0 の作業として、このプロンプトのうち「進め方のルール」「ドキュメントの更新ルール」「完了の報告について」「安全上の注意」を `AGENTS.md` に移してください。`CLAUDE.md` には `@AGENTS.md` と書いて読み込ませ、同じ内容を二重に持たないでください。あわせて `docs/README.md` の「開発の始め方」を `AGENTS.md` を案内する内容に更新し、移し終えたら `prompts/kickoff.md` を削除してよいか私に確認してください。

## ドキュメントの更新ルール

ドキュメントごとの寿命と扱いは `docs/README.md` の「ドキュメントの扱い」に従ってください。特に次の 3 つは必ず守ってください。

1. マイルストーンが完了したら、`docs/06-roadmap.md` から該当項目を消す
2. 未決事項が決まったら `docs/adr/` に ADR を書き、`docs/06-roadmap.md` から消す。ADR の形式は `docs/README.md` に従う
3. 実装と `docs/03-architecture.md`〜`docs/05-agents.md` がずれる変更をしたら、同じコミットでドキュメントも直す

## 完了の報告について

- 完了を報告する前に、テストと Lint を実際に実行し、実行したコマンドと結果の要約を報告に含めてください。実行していないものを「通った」と書かないでください。
- テストが通らないときに、テスト側を弱めて通すことはしないでください。必要だと考える場合は、理由を添えて私に相談してください。
- M2 が完了したら、このリポジトリ自身に `.menou.json` を置き、以降の開発では menou 自身のゲートを通してから完了してください。

## 安全上の注意

- `~/.claude/` と `~/.codex/` のグローバル設定は、私の許可なく変更しないでください。フックの動作確認は、一時ディレクトリに作ったサンプルリポジトリと、その中のプロジェクト単位の設定で行ってください。
- フックは私の権限で実行されます。ファイルの削除やネットワークアクセスを伴う処理を加えるときは、事前に説明してください。
- Claude Code と Codex のフック仕様は変わりやすいので、M2 と M3 に入る前に、`docs/05-agents.md` に載っている公式ドキュメントの最新版を確認してください。確認できない場合は、その旨を伝えて私に確認を求めてください。

## マイルストーン完了時の報告形式

- 作ったもの（ファイルと役割）
- 完了条件をどう確認したか（実行したコマンドと結果）
- 残った課題、気づいたリスク
- `docs/` の更新が必要な箇所
- 次のマイルストーンに進む前に決めてほしいこと
